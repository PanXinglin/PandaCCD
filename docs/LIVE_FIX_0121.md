# 0.12.1：Live取景方向与动态调色修正

日期：2026-11-03；版本：0.12.1+21。用户反馈开启Live后内外屏多个方向的取景异常，以及应用内、系统相册中的动态效果与静态封面不一致。

## 改动

Android Live不再并行开启相机录制与ImageAnalysis图像流。这一组合存在CameraX StreamSharing预旋转、插件重复补偿的已知问题，不能通过给某一款手机额外加90度解决。Live美颜改为每300ms对未加滤镜的取景器采样一次，最长边480像素，本地识别人脸并平滑坐标。没有逐帧CPU滤镜；取景效果、照片及动态仍共用Dart/GLSL。普通静态拍摄继续使用图像流，iOS的原有双流路径保持不变。取景采样不会包含控件、水印或已经瘦脸的画面，避免识别结果反复反馈；切换镜头/方向时丢弃旧坐标。

Android Bitmap视频解码输出误标为BGRA，实际缓冲区为RGBA，导致红蓝通道互换，视频帧进入LUT前的颜色就已错误。同步修正视频输入与人脸像素输入的通道识别，保留iOS的BGRA读取方式。修正后视频的开头、中间、结尾均验证实际带有同一CCD处理，并非只在封面显示效果。

新导出的动态源带像素版本标记。0.12.0已处理的Android Live重新编辑时，会校正旧动态源的通道顺序；未完成处理的原录制片段不会误校正，新格式重复编辑也不会重复交换。**已保存的旧成片不会自动被替换，可在作品库重新编辑并保存为新作品。**

## 验证

- 70项单元/界面测试通过，静态分析通过。
- Android36 ARM64实际相机预览：紧凑外屏尺寸、展开大屏尺寸；前后镜头四方向，比较开启Live前后的取景像素。两组共16场景通过。另加物理1712×1168、240dpi原生横向屏幕的前后镜头四向检查及重复切换。方向测试比较原图与90/180/270度及镜像候选，原方向始终最佳；不只检查控件对象，也不把模拟相机内容/曝光变化误判为转向。测试采样等待实际彩色纹理就绪，避免把初始化空帧作为方向基准。
- 原生编解码彩色哨兵保留红蓝通道；动态逐帧应用强偏色、饱和度、暗角和颗粒。视频与同参数封面的平均通道误差约2.82/255，与原始帧差异约46.44/255；0、0.3、0.7、0.9秒检查通过。
- 480像素真实人像取景采样通过ML Kit识别；前置镜像坐标转换、方向交接中在途检测作废通过原生测试。
- 测试代码：`integration_test/live_regression_test.dart`、`integration_test/live_face_snapshot_test.dart`；驱动：`tool/drive_live_regression_test.py`。展开屏测试传入`--dart-define=PANDA_QA_EXPANDED=true`，使用物理配置最短边至少600dp的AVD，不能将系统DPI覆盖误当物理屏幕切换。

未连接用户的小米真机，模拟器结果不能保证所有厂商Surface实现均相同。iOS整包及真机验证边界同0.12.0，未宣称新增通过。

## 依据

[Flutter #180075](https://github.com/flutter/flutter/issues/180075)记录录制与图像流并行时的重复旋转，以及StreamSharing改变预览缓冲区方向而原补偿不变的问题；本次通过避开该组合处理，没有对不同品牌叠加旋转常数。
