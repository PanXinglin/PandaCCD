# 0.7.0：快门反馈与导出耗时

日期：2026-10-27。

## 判断

用户反馈包括两部分：按下后只有转圈，无法明确感知拍到了照片；部分预设等待时间更长。源码确认旧版把原始相机拍摄、读文件、滤镜合成、PNG编码、本地写入和系统相册写入串在一个opening状态里。因此转圈的总时长不等于快门曝光时长，缺少成功反馈也会放大等待感。

本次没有连接用户手机，不能直接确认其某个机型预设究竟慢在哪一段。所有预设共用同一个GLSL程序，但参数、最终像素分布和PNG处理成本可能不同；不能仅凭预设名称归因于GPU滤镜慢，更不能声称模拟器测试代表用户真机。

## 交互

- 接受快门点击时调用Flutter轻触觉反馈，实际触感由设备及系统设置决定。
- 官方camera成功返回照片文件后，取景画面短暂暗闪，约130ms；不对曝光失败播放成功反馈。不使用强烈白屏，不是前置补光，不加入照片像素或水印。
- 暗闪初始即到可见峰值，并等待这一帧绘制后才开始大图处理，避免导出工作挤掉整个短动画。尊重系统减少动画设置。
- 相机图标持续保留；操作超过250ms才显示细进度环，避免快速任务也闪一下转圈。区分“拍摄中…”与“照片已拍好，正在保存…”，保存完成后沿用已有提示。
- 提示和动画都是独立、常驻的刷新层，延续0.6.2的机型栏位置保护。仍按单张处理完成后允许下一张，避免引入未设上限的后台导出队列和内存堆积。本次不是连拍功能。
- 默认拍后编辑和直接保存都保留，关闭屏幕动画并不会改变拍照/保存结果。相机接口提供的是照片文件返回时机，暗闪不是传感器曝光时刻的精确回调。

## 实际优化

1. 滤镜与水印合进同一个Picture，调用一次toImage。去掉一张完整中间图及第二次整图合成；输出尺寸、滤镜参数和PNG格式沿用原策略，不靠降采样换速度。
2. 自定义LUT复用已有GPU图片，通过Image.clone持有临时句柄，避免每张重新base64解码、解PNG和上传纹理。作品仍记录原始HALD，以便今后无损调参；所有临时句柄在导出后释放。
3. 保存得到新的PhotoEntry后直接加入作品列表，不再每拍一张扫描、解析和排序整个作品目录。进入相册和初始化时仍可刷新目录。
4. 图像及LUT临时句柄在进入磁盘/系统相册等待前释放，减少等待期间持有的GPU资源。

API依据：[Picture.toImage](https://api.flutter.dev/flutter/dart-ui/Picture/toImage.html)、[Image.toByteData](https://api.flutter.dev/flutter/dart-ui/Image/toByteData.html)、[Image.clone](https://api.flutter.dev/flutter/dart-ui/Image/clone.html)。clone复用底层图像并增加可独立释放的句柄，不是重新解码或复制所有像素。

## 测量与边界

Android36 ARM64模拟器、Impeller、软件GPU后端，Flutter debug，900×1200同一示例图，11种预设，开启水印。先预热一次，每个预设各测3次，用中位数比较。完整数据见[export-070.csv](benchmarks/export-070.csv)。

| 指标 | 结果 | 含义 |
|---|---|---|
| 旧版11个预设中位数之和 | 2540.43ms | 仅合成及PNG输出，不含相机/相册 |
| 新版同一指标 | 2436.44ms | 约减少4.1%，属于小幅改善 |
| 新版独立分段测量，33次光栅化中位数 | 2.7ms | 包含等待图像完成，不能当作纯GPU指令计时 |
| 33次读回+PNG编码中位数 | 232.9ms | 占该分段测试总导出时间约98.6% |

这组数据表明在该测试环境下，导出阶段的大头是图像读回与PNG输出，减少一次合成只能小幅提速；没有测量用户真机的相机驱动、闪光预曝光、存储或系统相册耗时，也不承诺全流程快4%。库重扫和自定义LUT复用的收益未计入上述纯渲染测试。3次样本、debug及软件GPU限制了结论的外推范围。

## 验证

- 23项自动化测试通过：成功拍摄的短暗闪、不拦截触摸、减少动画设置、延迟进度环、失败不暗闪不进入保存、保存阶段文字，以及连续拍摄机型栏稳定性。
- 11组预设+裁剪/旋转/颜色/位置/中文水印组合，与原两图合成参考实现逐通道比较，实际最大差为0；容差上限为1/255以允许后端的微小舍入差异。不宣称所有设备、所有参数或PNG编码字节始终一致。
- 完整PandaApp与真实模拟器相机流程：一次拍照触发一次可见峰值暗闪、保存成片成功，105次机型栏像素比较一致。
- 同步连续录屏127帧，检测到取景亮度短暂降低，机型栏保持原位置。[快门反馈录屏](screenshots/shutter-feedback-070.mp4)；[连续帧示意](screenshots/shutter-feedback-070.jpg)。相机内容是模拟器测试图，不是实拍样张。
- 触觉、实际速度、硬件闪光、折叠真机和iOS仍待设备验证。本次不改变0.6.0的硬件闪光兼容策略，也不声称修复了仍待真机确认的漏闪。
