# 0.10.3：系统窗口转向与取景衔接

2026-10-30，build15。保留原有设计，包含0.10.2的外屏图标方向和内屏稳定场景修复。

## 本版修改

1. 经用户2026-10-30明确允许，在Android启动壳中请求ROTATION_ANIMATION_SEAMLESS。API26以下保持原系统行为；该配置不实现相机采集、滤镜或原生业务功能。
2. 相机插件的Dart展示层在窗口变化后主动读取官方插件已有的UI方向接口，不再只等下一次姿态传感器事件。释放相机时移除监听并使未完成查询失效。
3. 窗口尺寸变化期间，用最后已绘制的GPU画面衔接350ms，避免新尺寸相机纹理尚未到达时露出空白。只在窗口变化时取GPU图层快照，不读取字节、不做逐帧CPU滤镜。快照在使用结束和页面销毁时释放。

核心LUT/GLSL代码及iOS原生工程未修改。Android窗口配置为用户明确允许的最小例外，不能再概括为“项目没有任何原生定制”。

## 验证

- 静态检查无问题，58项测试通过；新增检查证明等待新布局/新画面时仍能保留最后已绘制的像素，并且后续画面更新不会覆盖已保留的图像。
- API36大窗口模拟器：1800×2200、420dpi、最短边686dp，ignoreOrientationRequest=true。
- 系统左横→竖→右横→竖、真实相机拍照、通知栏持续失焦后返回测试通过，相机/纹理/预览/快门/机型列表保持同一对象。
- 增加window-only运行：固定重力传感器，不补发新姿态事件，只改变系统窗口方向，同样完成转向和横竖拍照。用来验证窗口刷新不再依赖“再动一下手机”。
- 系统窗口属性实见rotAnim=SEAMLESS；正常main.dart包录屏见screenshots/inner-rotation-0103.mp4。
- 正常main.dart入口APK版本0.10.3/build15，区别于集成测试包。

## 实测边界

模拟器不能证明小米/三星真机完全无闪动；不同系统也可能在不满足连续旋转条件时使用替代动画。iOS原生构建和真机仍待验证。窗口变化期间的350ms保持帧会短暂暂停画面更新，这是衔接手段，不宣称这一时段仍有连续60fps。
