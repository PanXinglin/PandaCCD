# 0.6.0：切屏过渡、闪光兼容与自定义水印

日期：2026-10-26。用户补充：后置在“开启”模式仍有漏闪，不是自动模式的正常判断。本次不把软件接口调用成功等同于硬件确实发光。

## 相机过渡

移除相机页“体验示例照片”入口与默认宣传占位。权限被拒、没有摄像头、启动失败或GPU后端不支持仍需明确提示，保留失败时的重试/相册导入。

切屏重新初始化、性能降档、切镜头和闪光模式导致的会话更换，在释放旧相机前尝试保存一张取景快照。新纹理在快照下方挂载，等待250ms后显示；过渡期间快门和相关操作暂不可点。快照只在这些事件发生时读回一次，逻辑像素比例1，完成后释放，不是逐帧CPU滤镜。显示表面提前失效而无法截图时使用深色过渡，不出现宣传页。

窗口/显示改变稳定450ms才校准，并区分“已应用”与“当前观察到”的几何状态：旋转过程的中间尺寸若恢复原值就取消校准，避免不必要的相机重开。开始重建时先标记busy，再释放旧控制器，消除空控制器短暂被当作空闲状态的间隙。相机尺寸保持0.5.0的等比容纳规则。

## 后置强制闪光兼容

已确认的事实：0.5.0使用固定60fps预览，切屏和自动性能降档也可能重建会话；此前只修复了闪光选择恢复，尚无用户真机发光证据。不能由现有信息确认唯一漏闪根因。

0.6.0的兼容处理：

- 开启/自动闪光使用30fps相机会话，关闭闪光后恢复原帧率目标；如果性能监测已降档，则维持30fps。单纯启用闪光不降低分辨率档位。
- 会话重建后恢复该镜头已成功选择的闪光模式，拍照前重新设置自动曝光及所选闪光，再调用官方takePicture。过渡快照覆盖新纹理准备期间，避免切换模式时出现示例页。
- 菜单明确区分“开启（每次拍照）”和“自动（由相机判断）”。前置不提供闪光菜单，服务层也拒绝向前置设置非关闭模式；未实现白屏补光。
- 不使用短时常亮手电筒模拟同步闪光，不擅自重拍第二张。硬件、温度、电量和厂商相机管线仍可能限制闪光；真实灯珠是否每次触发，须在反馈设备上实拍复核。

依据：[CameraX闪光选项](https://developer.android.com/media/camera/camerax/take-photo/options)、[AOSP曝光/预闪状态机](https://source.android.com/docs/core/camera/camera3_3Amodes)、[官方Flutter camera_android_camerax实现](https://github.com/flutter/packages/blob/main/packages/camera/camera_android_camerax/lib/src/android_camera_camerax.dart)。这些资料说明闪光依赖曝光/预闪和拍摄会话；没有证明该小米设备的漏闪由60fps引起，30fps是本次的兼容措施。

## 水印

- 设置与暗房共用颜色下拉：琥珀黄色 / 复古红色。去掉“勾选红色、不勾选黄色”的开关。
- 位置改为左上、右上、左下、右下的明确选择。
- 支持最多32字自定义文字，留空恢复“熊猫CCD”。可选择是否附加当前机型名称，例如G12 INSPIRED；关闭后可只显示自己的文字。
- 日期戳与文字水印独立开关。颜色和位置对两者生效；日期格式、字体和自由拖动位置本次不自定义。
- 预览与成片共用绘制函数；设置持久化，作品编辑记录保留自定义文字、颜色、位置与机型附加开关。旧记录没有新字段时沿用熊猫CCD及机型名称；历史成片不自动改写。

## 验证

18项自动化测试：增加颜色/位置选择、自定义文字应用及清空、旧配置兼容；原图再次编辑的PNG一致性测试加入中文自定义水印及关闭附加机型；测试闪光会话在30/60fps间切换、前置拒绝硬件闪光、镜头选择恢复及曝光/拍照调用。

Android36 ARM64模拟器：内外屏尺寸交接时观察到过渡快照，未出现“体验示例照片”；直接拍照→相册恢复原参数编辑→收起→切前置隐藏闪光入口→切回后置恢复入口，流程通过。模拟器不具备真实闪光灯，不能据此验收用户反馈的硬件漏闪。iOS构建、折叠真机和真实发光仍待对应设备验证。
