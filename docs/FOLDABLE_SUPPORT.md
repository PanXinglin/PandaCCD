# 折叠屏、闪光灯与拍后流程（0.5.0）

核查日期：2026-10-26。本页说明当前实现与实际验证范围，替代0.4.0的“大屏仍强制跟随重力、拍照临时锁方向”策略。

## 调研结论

| 来源 | 与本次问题相关的结论 | 工程处理 |
|---|---|---|
| [Android相机预览](https://developer.android.com/media/camera/camera2/camera-preview) | 折叠可只改变窗口形状，不改变设备旋转；图像须保持像素比例 | 窗口决定控件布局，camera插件决定相机图像方向；等比contain显示 |
| [Android折叠设备相机指南](https://developer.android.com/media/camera/camera2/foldable-devices) | 内外屏交接可能切换物理相机，传感器方向/镜头朝向会变化，不应缓存旧特征 | 监听Flutter窗口/显示尺寸与像素密度，稳定450ms后重新枚举并初始化相机，保留仍可用的镜头名与模式 |
| [Google对新三星Galaxy设备的指南](https://android-developers.googleblog.com/2026/07/optimize-galaxy-screen-sizes.html) | 可能是自然横屏内屏；使用实际应用空间、避开分隔铰链，保持折叠前后状态 | 不做品牌或型号白名单；展开窗口交还系统方向管理，使用Flutter DisplayFeatureSubScreen避开系统上报的分隔铰链 |
| [Apple iPhone Duo准备指南](https://developer.apple.com/iphone-duo/prepare/) | 握持方向不能代表窗口形状；随窗口变化重新布局，适配安全区；最新SDK影响展开显示范围 | 控件按LayoutBuilder重排，SafeArea处理边缘；不依赖iPhone/iPad类别、固定尺寸或设备名；Duo完整边到边体验需Xcode/iOS27.1 SDK构建与实际验证 |

这套规则覆盖窄外屏、宽外屏、近方形内屏、横向大折叠和多窗口的布局类别，供小米、三星、Pixel及其他品牌共用。布局适配不等于所有相机硬件和厂商逻辑镜头切换已经认证。

## 压扁问题的处理

源码检查发现两个风险点，未拿到用户设备运行日志，不能把它们描述为该设备唯一根因：

1. 0.4.0把手机原始重力方向传给lockCaptureOrientation；官方CameraPreview也会使用lockedCaptureOrientation计算比例，但Android插件的纹理变换另由显示旋转决定。内屏上两种方向可能不一致。0.5.0取消该临时锁定，预览与拍照共用官方插件的方向依据。
2. 外层取景框与CameraPreview分别监听方向。内外屏交接时，旧竖向预览可能短暂被外层新横向紧约束拉伸。现在给预览单轴约束，先按自身比例布局，再通过CameraTextureFit等比放入外框；方向事件先后不同只会暂时留边，不会强制改变像素比例。

普通手机/小外屏保留0.4.0已通过用户验证的稳定握持方向请求；窗口或显示屏最短边达到600逻辑像素时释放该请求，避免把自然横屏内屏当作竖屏手机，也遵循Android16大屏方向请求限制。相机拍照不再直接使用重力方向。退出、后台和返回路径保留生命周期管理。

窗口或显示尺寸、显示标识、像素密度或系统上报的折叠状态改变时重新初始化；单纯宽高互换不反复重开相机。切屏过程中发生拍照时，校准排到拍照处理结束后执行。刷新后重新获取相机描述，按名称恢复可用镜头；硬件的逐帧物理镜头变化仍依赖官方camera/CameraX/AVFoundation能力，没有新增平台私有接口。

分隔铰链由系统上报时，相机和应用导航选择左侧/上方可用区域，避免把快门放到铰链上；这不是三星原生Flex双面板、铰链角度检测或三折叠专用模式。系统不报告的折痕不能由应用自行推断。

## 闪光灯

- 后置与前置镜头分别记住当前会话内成功设置的模式。前置不支持闪光时，不清除后置之前的选择。
- 拍照前再次通过官方camera应用所选off/auto/always模式，再执行takePicture；重新初始化后也恢复该镜头的模式。
- 相机未就绪或模式不支持时提供提示，不把失败伪装成“已开启”。保留自动与强制开启的区别；不通过短时常亮手电筒代替同步闪光。
- 自动闪光由相机判断是否需要；前置不保证有硬件闪光，也未加入白屏补光。模拟器没有真实灯珠，本次不能验证硬件确实发光。需在后置选择“闪光灯开启”进行实拍复核。

## 拍后流程

设置 → 拍照后直接保存，默认关闭，老版本设置缺少此字段时也保持关闭。

| 模式 | 按快门后 | 后续编辑 |
|---|---|---|
| 默认：拍后编辑 | 进入CCD暗房，手动保存 | 沿用原流程 |
| 直接保存 | 应用当前机型/参数/水印，先提交作品库再尝试系统相册，留在取景页 | 作品相册 → 照片 → 再次编辑 |

直接保存始终保留应用内原图，同时写编辑记录，包含当时的机型、参数、自定义HALD、日期、水印、旋转与裁剪。后续改变当前机型也不影响旧作品的再次编辑；从原图重算，不重复叠滤镜或水印。编辑结果保存为新作品，原作品保留；直接保存来源的新作品继续保留可编辑源。删除作品同时删除对应原图和编辑记录。

原图和编辑记录仅在应用私有作品库，系统相册只写成片。卸载应用会丢失私有原图。原有“同时保留原图”开关继续控制普通拍后编辑模式；没有原图的历史照片不能无损还原，只能在已有成片上继续编辑。相册权限拒绝仍保留本地作品并提示；直接保存提示不阻挡快门和相册按钮。

## 实际验证

- 16项自动化测试通过。真实CameraPreview组件在7种窗口、4种方向下模拟外框与纹理方向不同步，验证两个轴的缩放相同；测试前后镜头闪光选择、重新初始化、三种拍照模式调用，禁止拍照时临时锁定方向。
- 直接保存测试拒绝系统相册权限，确认原图/参数记录仍落盘；改变当前机型后重新打开原记录，不改参数再保存，输出与首张PNG逐字节一致，避免重复效果。删除同时清理编辑记录与原图。
- Android36 ARM64模拟器：1168×1712/420dpi → 2208×1840/420dpi → 原尺寸，检查重新初始化、直接拍照不跳编辑、相册恢复G12/0.73颗粒并再次编辑，流程通过。尺寸变化模拟显示交接，不代表实际物理铰链/厂商相机切换。
- 同一模拟器在系统锁定竖屏时，输入左右横握与竖握加速度，横拍直接得到1280×720输出，恢复竖屏，通过。
- 未连接小米/三星/其他品牌折叠真机，未安装完整Xcode；iPhone Duo编译、模拟器、真机未验证。相机硬件闪光、前置逻辑镜头切换、OEM内外屏策略、持续性能和系统分享需真机回归。

建议真机验收：后置/前置各测外屏打开→展开→左右横握→拍照→收起；检查圆形物体不变椭圆、人脸比例、取景与成片方向；后置分别测关闭/自动/开启；两种拍后模式各测一次保存与相册再编辑。优先小米反馈设备，其次三星自然横屏内屏、Pixel类宽内屏，以及Duo最新SDK环境。
